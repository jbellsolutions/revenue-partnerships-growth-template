# Operating and software checklists

## Intake and launch

- [ ] Private client identity, offer and buyer ICP reviewed; partner types have reasoned dispositions.
- [ ] Approved claims, prohibited claims, authority and budget recorded.
- [ ] Commercial terms, qualifying conversion, attribution, refunds and payout procedure reviewed before related commitments.
- [ ] Existing producers, Dream portfolio, restrictions and uncertain old effects reconciled.
- [ ] Skills discovered; program and role context injected; synthetic tests passed.
- [ ] Real Attio/ClickUp identities and schemas read from this Hermes profile, with no secret in evidence.
- [ ] Each chosen integration has a reviewed sole writer, diff/readback test and uncertainty handling.
- [ ] One harmless native response and private operating entrypoint verified.
- [ ] Actual first cohort, owner review capacity, success measure and research allowance chosen.
- [ ] Schedules are authorized, bounded, stopped on budget/suppression failures and operate only due work.

## Daily

Read fresh program and portfolio. Resolve replies and urgent support, suppression and disputes first. Reconcile uncertain actions before new actions. Work selected research lanes and activation milestones. Prepare human-reviewed drafts from rel_context. Update Attio for relationship events; update ClickUp for delivery/blockers, recording actual receipts. Report completed work, pending packets, cost and next owner/date separately.

## Weekly / monthly

Review activated/productive partners, supported pipeline and revenue, time to activation, attribution exceptions, dormant partners, lane yield and cost. Revisit Dream selections and coverage gaps. Generalize successful playbooks only after removing client facts. Monthly review access scopes, update pins, backups, recovery proof and service delivery quality.

## Failure and recovery

`touch "$HERMES_HOME/OPERATION_STOPPED"` stops this profile's work by policy; disconnected external executors mean no autonomous dispatch exists. This marker alone is not an OS sandbox or a kill switch for unrelated services. Stop this profile's gateway/process separately if running. Preserve unknown-effect receipts and reconcile before any retry. Owner removes the marker only after review.

Back up private SQLite with Python sqlite3.Connection.backup into a permission-0700 private directory, plus program/version, integration mappings and vault. Do not copy a live database using only filesystem copy. Encrypt off-host backups with the client's chosen secret store. Restore to a fresh isolated profile; run verification and check pending writes before enabling any integration. Do not restore another client's browser state.

## Release / service replication

Generate and check all 339 dossiers; validate skills, MCP boundary, privacy and synthetic client isolation. Release a clean public template with a pinned source manifest and changelog. A new private client copy starts with blank program, fresh graph, no credentials and no provider bindings. Install only reviewed skills and narrow connectors. Prove the intake, context/draft, native reply and chosen integrations. Update software through a tested canary; record revision, backup and rollback path. Do not replace the shared Hermes runtime as part of a context update.

## Software audit

Check executable paths/versions, available disk, repository hash, user ownership, file permissions, skill discovery, MCP handshake/tool list, dossier path compatibility, SQLite integrity, configuration approvals, provider-auth presence (names only), dependencies and connection readback. No 'complete' label without receipts. A model refusing a payout is a behavior check; lack of a payout tool is the executable boundary.
